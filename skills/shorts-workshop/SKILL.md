# 타타쿠 쇼츠 공방 (편집기 v2)

사용자 PC 의 `C:\Users\eofus\Desktop\쇼츠작업` 에서 도는 로컬 웹 편집기(127.0.0.1:8765)로
고양이·동물 클립 5개를 랭킹 쇼츠로 만든다. 사용자는 링크 모으기·클립 고르기·라벨·버튼만 하고,
**대본과 업로드 자료는 Claude 가 채팅으로 요청받아 만든다.** 편집기는 Claude 를 직접 부를 수 없다.

## 흐름과 역할

| 단계 | 누가 | 결과 파일 |
|---|---|---|
| 1. 클립 수첩 — 링크 복사 → 자동 기록, 아이디는 사용자가 프로필에서 직접 붙여넣기 | 사용자 | `클립수첩.json` |
| 2. 쇼츠 구성 — 클립 5개(📂 폴더에서), 라벨, 시작·끝, 목소리·기본 감정 | 사용자 | `구성.json`, `voices.json` |
| 3. "대본 만들어줘" | **Claude** | `대본.json` |
| 4. 들어보고 다듬기 → 🎬 한 번에 완성하기 (바뀐 줄만 음성 생성 → 구성 영상 → 더빙) | 사용자 PC | `voice/*.wav`, `output/완성본.mp4` |
| 5. "업로드 준비해줘" | **Claude** | `업로드정보.json`, `output/썸네일_*.png` |
| 6. ✨ 새 쇼츠 시작하기 → `보관함/날짜_제목/` 으로 이동, 디자인 설정은 유지 | 사용자 | |

타입캐스트 API 는 클라우드·데스크톱 VM 모두 막혀 있으므로 음성 생성은 반드시 사용자 PC 에서 돈다.
영상 분석·썸네일은 데스크톱 VM(ffmpeg 있음)과 클라우드 컨테이너(Korean 폰트, PIL)에서 한다.

## "대본 만들어줘"

1. 데스크톱 VM 에서 `구성.json` 을 읽어 순서(`order` 5to1 이면 5위부터)와 클립별 `start/end`, 라벨, `brief`(메모), `voiceEmo`(목소리별 기본 감정)를 확인한다.
2. 클립마다 0.7초 간격 프레임 시트(8열, 초 표시)와 0.25초 RMS 를 만든다. 시트는 `쇼츠작업/분석/` 에 쓰고 스테이징해서 본다 (VM 홈은 스테이징 불가).
3. 동작이 터지는 순간을 찾아 **동작 0.2~0.4초 직전**에 대사를 둔다. 각 클립 첫 줄은 내레이터의 "N위, 라벨" 소개.
4. `대본.json` 은 리스트, 줄마다:
   ```json
   {"speaker":"narr|cat","clip":5,"at":2.8,"slot":1.4,"text":"놀아줘옹!",
    "emotion":"toneup","intensity":1.2,"speed":1.1,"pitch":1}
   ```
   - `clip`=랭크, `at`=그 클립 안의 초(트림 시작 기준), `slot`=허용 길이. 완성 영상 시각은 서버가 계산한다.
   - 감정은 목소리가 지원하는 것만 (normal happy sad angry toneup tonedown whisper 가 보통). 강도 0~2, 속도 0.5~2, 높낮이 -5~+5.
   - 한 줄 15자 이내, 슬롯은 `글자수/6.5 + 0.3` 초 이상. 같은 클립 안에서 줄이 겹치지 않게 (`at+slot` < 다음 `at`).
   - 내레이터는 상황 설명, 캐릭터는 고양이 속마음(짧게, "~옹").
5. `device_commit_files` 로 `쇼츠작업\대본.json` 에 쓴다. 편집기는 파일이 바뀌면 다시 읽는다 (사용자는 새로 켠 화면 기준).

## "업로드 준비해줘"

`업로드정보.json`:
```json
{"titles":["…","…","… #shorts"],
 "thumbs":[{"file":"썸네일_1_….png","title":"① …","idea":"왜 이 장면인지","frame":"약 39.5초 (3위 …)"}],
 "intro":"설명란 첫 문단", "hashtags":"#고양이 … #shorts",
 "tags":"쉼표, 목록", "pinned":"투표형 고정 댓글 + 저작권은 원작자에게 있다는 안내"}
```
- 설명란 = intro + (편집기가 자동으로 만드는 출처 목록) + hashtags. 출처를 따로 쓰지 않는다.
- 썸네일 3장: 1080×1920, 각 클립의 가장 강한 프레임, 상단 분홍 배지 + Black Han Sans 큰 글씨 2줄(흰/노랑 또는 보라) + 아래 캡션. 얼굴 위에 글씨가 덮이지 않게 사진을 아래로 민다. Black Han Sans 에는 `…` `·` `→` 와 이모지가 없다.
- 썸네일은 `output\` 에 쓴다. 한글 파일명은 전송 중 다른 글자로 바뀔 수 있으니 커밋 후 `ls` 로 확인하고 `mv` 로 바로잡는다.
- 저작권: "원작자 허락" 같은 사실이 아닌 문구는 쓰지 않는다.

## 편집기를 고칠 때 (배포 규칙)

- 소스는 `editor_server.py`(stdlib HTTP 서버), `shorts_layout.py`(PIL 오버레이 + ffmpeg 렌더), `sources.py`(클립 수첩), `shorts_tts.py`(타입캐스트 엔진), `web/index.html`(단일 파일 UI), `편집기.bat`.
- 고칠 때마다 컨테이너에서 가짜 타입캐스트(mock) 서버 + Playwright 스크린샷으로 확인한 뒤, **새 파일 이름으로 스테이징**해서 `device_commit_files` (같은 stagedPath 는 캐시된다). 커밋 후 md5 로 확인.
- 바뀐 서버는 사용자가 **검은 창을 닫고 편집기.bat 을 다시 실행**해야 적용된다. bat 은 8765 포트를 쓰는 예전 서버를 먼저 끈다. 화면 위 "예전 버전" 띠가 뜨면 같은 안내.
- ffmpeg 는 PATH 에 없으면 `imageio-ffmpeg` 의 바이너리를 쓴다 (bat 이 설치). ffprobe 없이 `ffmpeg -i` 출력으로 길이·오디오 여부를 읽는다.
- 화면은 칸마다 try/catch 로 따로 그린다. 한 칸 오류가 다른 칸을 막지 않게.

## 사용자 취향 (지켜야 할 것)

- 버튼 하나, 붙여넣기 한 번으로 끝나게. 파일명 목록 대신 썸네일·폴더 창.
- 출처 아이디는 자동 추정으로 확정하지 않는다. 제목의 "○○님" 은 힌트로만 보여준다.
- 라벨 글자색 = 그 순위 숫자 색. 글씨 뒤 어두운 배경·외곽선 금지 (깨져 보인다).
- 업데이트가 있으면 1080×1080 따라 하기 카드 + 네이버 썸네일(1200×675, 가운데 675 안전영역) + 블로그 글 + 깃허브 CHANGELOG 를 같이 만든다 (shorts-tts-timing 스킬의 카드 규칙).
